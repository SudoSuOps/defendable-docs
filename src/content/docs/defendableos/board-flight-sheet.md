## What this artifact is

This is the same flight-sheet pattern Mr. Defendable used to close $8B in industrial CRE. A board reading this should be able to make an approve/reject decision in 15 minutes.

## Flight sheet structure

| Field | Read |
|---|---|
| Assignment | Class A 5-cap DefendableOS engagement |
| Asset | AI defense protocol · trust operating system |
| Principal | (the customer's principal) |
| Mandate | Build / deploy / operate the defense layer |
| Board Read | This is not a website assignment. This is a category-definition assignment. |
| Probability of Close | STRONG (if vendor understands language before writing code) |
| Primary Risk | Hiring a normal web/app shop that builds pages but misses doctrine |
| Disqualifier | Generic AI SaaS language |
| Winning Strategy | Build the house around vocabulary · receipts · Tribunal · DDEED rails |

## The 4 vendor risk flags (board disqualifiers)

| Vendor type | What they will build | What they will MISS |
|---|---|---|
| Normal web shop | Pages | THE TRUST SYSTEM |
| Normal AI shop | Models | THE RECEIPTS |
| Normal SaaS shop | Dashboards | THE BOOKS-AND-RECORDS |
| Normal dev agency | Code | THE CRE LANGUAGE · broker-grade client trust |

The board should WALK from any vendor that exhibits any of these.

## Acceptance criteria

1. Principal understands DefendableOS in 90 seconds.
2. The site does not sound like generic AI SaaS.
3. The app shows trust · NOT vanity metrics.
4. Every dashboard dial maps to vocabulary AND receipts.
5. A sample assignment can be routed · scored · receipted · AND deeded.
6. The build preserves founder language.
